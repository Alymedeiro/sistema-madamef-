# Fase 1 — Base: Plano de Implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar a Fase 1 do sistema Madame Fê Clinic — login com 3 perfis, equipe, clientes, serviços/produtos, agenda completa, pagamento do atendimento e caixa do dia, painel do dia, PWA e identidade visual.

**Architecture:** Next.js (App Router) com Server Components para leitura e Server Actions para escrita, falando com Supabase. Toda permissão é aplicada no Postgres via RLS + funções `security definer`; a tela apenas esconde o que o banco já nega. Regras de negócio puras (agenda, dinheiro, caixa, status) ficam em `src/lib/dominio/` e são testadas com Vitest.

**Tech Stack:** Node 22, pnpm, Next.js 15, React 19, TypeScript (strict), Tailwind CSS 4, shadcn/ui, `@supabase/ssr` + `@supabase/supabase-js`, Supabase CLI (local via Docker), pgTAP (`supabase test db`), zod, `@date-fns/tz` + date-fns 4, `@dnd-kit/core`, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-02-sistema-madame-fe-design.md` (seções 3, 4, 5.1–5.3, 5.5, 5.6, 6.1–6.4, 7, 8, 9-Fase 1, 10)

## Global Constraints

- Todo texto de interface em **português do Brasil**.
- Fuso fixo **`America/Sao_Paulo`** para exibir e interpretar datas, independente do fuso do aparelho. Datas/horas gravadas como `timestamptz`.
- Moeda BRL; **valores sempre em centavos (inteiros)** no banco e no domínio.
- Perfis: `dona` | `recepcao` | `profissional` (enum `perfil`).
- Status de agendamento: `pendente` | `confirmado` | `atendido` | `faltou` | `cancelado`; cores 🟡 pendente · 🔵 confirmado · 🟢 atendido · 🔴 faltou · ⚫ cancelado.
- Formas de pagamento: `pix` | `dinheiro` | `debito` | `credito` | `credito_parcelado` | `a_receber`.
- Toda tabela: `id uuid default gen_random_uuid()`, `criado_em`, `atualizado_em` (trigger). Exclusão lógica (`ativo = false`) em registros com histórico.
- **RLS habilitado em todas as tabelas**; colaborador inativo (`ativo = false`) não acessa nada.
- Segredos (`SUPABASE_SERVICE_ROLE_KEY`) só no servidor; nunca em arquivo importado por Client Component.
- Cores (tokens Tailwind): `blush #FEEDF3`, `blush-forte #F8D7E3`, `ouro #986818`, `ouro-escuro #805008`, `ouro-claro #E8C979`, `texto #3D2B1F`, `branco #FFFFFF`. Texto dourado só em `ouro-escuro`.
- Fontes (`next/font/google`): títulos **Cinzel**, decorativo **Great Vibes**, texto **Montserrat**. Logo usado como imagem: `public/brand/logo-madame-fe.png`.
- Áreas de toque ≥ 44 px; contraste mínimo WCAG AA.
- Viewports de teste: **1440 px**, **1024 px**, **390 px**.
- Sessão expira após **12h** de inatividade.
- Sobreposição de agendamentos do mesmo profissional **nunca** é permitida; fora da jornada é permitido só para dona/recepção com confirmação.

## Review Focus

1. **Aparelho em outro fuso** (tablet configurado em UTC): horários devem aparecer e ser gravados como horário de São Paulo → teste em Task 2 roda com `TZ=UTC`.
2. **Duas pessoas marcando o mesmo horário ao mesmo tempo**: o segundo salvamento deve falhar com "Este horário já está ocupado para esta profissional." (constraint do banco, não só a checagem da tela) → testes em Task 4 (pgTAP) e Task 10 (`mensagemErroBanco`).
3. **Colaborador desativado com sessão aberta**: deve perder acesso na hora, sem esperar o login expirar → teste pgTAP em Task 3 e banimento do usuário em Task 7.
4. **Cliente duplicada** (mesmo CPF com/sem pontuação; WhatsApp digitado como `(11) 98765-4321`, `11987654321` ou `+55 11 98765-4321`): CPF único após limpeza e telefone normalizado; busca acha por qualquer formato → testes em Task 2 e Task 9.
5. **Centavos perdidos no parcelamento e no fechamento de caixa** (R$ 100,00 em 3x; digitar "1.234,5"): soma das parcelas = total, parse aceita formatos brasileiros → testes em Task 2 e Task 12.
